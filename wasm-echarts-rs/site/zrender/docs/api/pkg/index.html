总览与何时使用

业务代码走 JS facade（@wasm-zrender）。 pkg/ 是 wasm-bindgen 产出的 handle，给调试、echarts 注入 native，或绕过原型链。

不要从业务 import '../pkg/wasm_zrender.js'。 echarts 页不要再加载这份 zrender wasm：echarts 自己的 pkg 会 setNative 进同一套 facade。

何时才碰 pkg

场景 怎么用
文档站 / 直接构图 只 import @wasm-zrender。入口会加载 standalone pkg 并注入 native-core。
wasm-echarts crates/wasm-echarts/js/native.js 把 echarts 自己的 pkg 注入 zrender 的 setNative。图元 native 类来自 echarts wasm，不是第二份 zrender wasm。
调试 / 绕过原型链 直接 new native.Rect(opts) 得到 handle。没有 instanceof Path，也没有 JS 上的 x / style / shape getter。 
// 推荐（facade）
import initWasm, { init, Rect } from '@wasm-zrender';
await initWasm();
const rect = new Rect({ shape: { x: 0, y: 0, width: 40, height: 20 } });
rect instanceof Path; // true

// 调试才碰 handle（不要当公开 API）
import * as pkg from '../../../pkg/wasm_zrender.js';
const handle = new pkg.Rect({ shape: { x: 0, y: 0, width: 40, height: 20 } });
handle instanceof pkg.Path; // false

两层对照

pkg 类是 wasm-bindgen 生成的；同名 JS 类在 js/*.js 里包装它。 叶子构造走 _bindNative(new native.Xxx(opts))。

JS facade pkg handle
导入 @wasm-zrender → js/ pkg/wasm_zrender.js（内部）
原型链 Rect → Path → Displayable → Element 没有。每个类是独立 wasm 类型
变换 / style / shape JS getter/setter，再同步 native 几乎只有 attr / setShape / setStyle / position
链式调用 add / attr 返回同一个 JS 对象 成功时常返回 undefined；on / attr 会 new 一个同 id 的新 handle
工具模块 js/tool/ 有实现 matrix() 等返回空对象，见空壳页
Group 子树遍历 children / eachChild / traverse 没有。仅 facade

注入路径

js/native-core.js 不静态 import pkg。谁先 setNative(mod)， facade 的 native.Rect 就指向谁。 

// wasm-zrender/js/native.js（文档站）
import * as standalonePkg from '../pkg/wasm_zrender.js';
setNative(standalonePkg);

// wasm-echarts/js/native.js（图表页）
import * as echartsPkg from '../pkg/wasm_echarts.js';
setNative(echartsPkg); // 同一份 wasm，内含 zrender 类

Rust 侧 echarts 还直接调 crate 函数（insert_renderer / attach_host / with_zr），这些没有 #[wasm_bindgen]，JS 的 pkg 里看不到。见 不要直接用的符号。

pkg 分页

  • 顶层函数与 ZRender — init / refresh / 事件
  • 图元与样式类 — Shape / Group / 渐变 / 几何
  • 空壳与不要直接用的符号 — 空 tool、抛错基类、仅 Rust 符号

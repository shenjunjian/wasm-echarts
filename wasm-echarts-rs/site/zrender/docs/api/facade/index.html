总览与约定

公开面是 crates/wasm-zrender/js/index.js。 default 是 wasm-bindgen 的 initWasm；命名导出才是 zrender API。

导入

文档站 Vite alias @wasm-zrender 指向 js/。 入口会先加载 native.js，把 standalone pkg/ 注入 native-core.js，图元构造才能拿到 native 类。 

import initWasm, { init, Rect, Group } from '@wasm-zrender';

await initWasm();
const zr = init(canvas, { width: 480, height: 360 });

不要直接 import pkg/wasm_zrender.js。 echarts 页不要再加载这份 zrender wasm，见 pkg 导出（echarts 用自己的 setNative）。

default 即 initWasm 补充

与 wasm-bindgen --target web 一致：默认导出是异步加载 .wasm 的函数。官方 zrender 没有这一步；这是 WASM 宿主必需。

参数 类型 说明
module_or_path? string | URL | Request | Response | BufferSource 可选。不传则按打包路径加载 wasm_zrender_bg.wasm 
import initWasm from '@wasm-zrender';
await initWasm();

构造约定：super() 不建 native

facade 的 Element / Displayable / Path 基类 constructor 只初始化 JS 字段。真正的 wasm handle 由叶子类 _bindNative(new native.Rect(opts)) 挂上。

  • new Path(opts) 才创建 native；子类只 super()。
  • new Displayable() 可作原型祖先，不创建 native。rust / pkg 的 Displayable 构造会抛「抽象基类」。
  • 叶子构造后若传入 opts，再 this.attr(opts)，保证 getter （x / shape / style）与 native 同步。
new Rect({ shape: { x: 0, y: 0, width: 40, height: 20 } })
  instanceof Path;       // true
new Circle() instanceof Displayable; // true
new Group() instanceof Element;      // true

可对照 shapes 示例。

opts 公共字段 官方

图元构造 / attr 都认这些字段（解析在 bridge/opts.rs）。

字段 类型 默认
x y 或 position number / [x, y] 0
scaleX scaleY number 1
rotation number（弧度） 0
originX originY number 0
z z2 zlevel number 0
silent ignore invisible boolean false
name string ''
draggable boolean | 'horizontal' | 'vertical' false
style / shape object 见图元页

skewX/Y、anchorX/Y 后置，不要当已对齐。

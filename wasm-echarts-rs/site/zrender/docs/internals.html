底层原理

给能读 JS、想搞懂 WASM 的前端：引擎用了哪些 crate、相对 vl-convert 补了什么、 普通数据 / 函数 / 图像怎么过桥。三层定位见 站点首页。

从 facade 到 RGBA

业务 / site → js/index.js → pkg handle → rust-zrender → RGBA → putImageData

wasm-echarts 与 wasm-zrender 是 sibling，共用同一份 ZRenderer， echarts 页不得再加载 wasm-zrender/pkg。

rust-zrender 依赖

路径 crates/rust-zrender。纯 Rust 引擎，无 wasm-bindgen，可 cargo test。浏览器入口在 wasm-zrender 的 facade / pkg。

crate 为什么用
vl-convert-canvas2d 离屏 Canvas2D（tiny-skia + cosmic-text）。Painter 真正落笔的地方
tiny-skia 补官方有、vl-convert 无的阴影（shadowBlur / Offset / Color）
kurbo 路径 winding / stroke 命中。不靠浏览器 isPointInPath
csscolorparser CSS 颜色字符串（含阴影色）
thiserror BackendError / FontRegistryError

相对 vl-convert 的补齐

官方 canvas 有、vl-convert 没有的能力，写在 crates/rust-zrender/src/canvas/backend/ 与 contain/。

补齐 位置 行为
阴影 backend/shadow.rs tiny-skia 画路径 → box blur → offset，再合成进 RGBA
命中 contain/path.rs 填充走 winding；描边走 kurbo stroke 距离；带 transform。Handler 反向扫 displayList，clip 链过滤
径向渐变 r0 canvas/helper.rs 映射到 RadialGradientParams.r0；global: false 时按包围盒缩放
lineDash 字符串 graphic/style.rs 'dashed' / 'dotted' / 'solid' 对照官方 dashStyle.ts；另有 lineCap / lineJoin / miterLimit
Pattern 变换 helper.rs + 样式 x / y / scaleX / scaleY / rotation
字体热更新 font_registry.rs registerFont 后把全局 fontdb 同步到已创建的实例（update_font_database）

仍未做：conic gradient、CSS filter。见 与官方差异。

绘制管线

ZRenderer 把 Storage + Painter + Handler 合成一个实例。 refresh() 全量重画，同步返回 RGBA。

Element 树 → displayList → Painter / brush → get_rgba()

DFS 展平 Group / Path / Image / Text，再按 zlevel / z / z2 timsort。 多 zlevel 时各 Layer 离屏合成。clip 链在 brush 前 clip()。

步骤 源码 做什么
场景图 storage/ 节点池 + 根列表；ChildRef 为 Group / Path / Image / Text
排序 storage/timsort.rs 对齐官方 displayList 稳定排序
落笔 canvas/brush.rs、image_brush.rs、text_brush.rs fill / stroke / clip / transform / alpha；文字走 cosmic-text
取像素 CanvasBackend::get_rgba Vec<u8>，宽 × 高 × 4

JS ↔ WASM：三种过桥

wasm-zrender 的桥在 crates/wasm-zrender/src/bridge/ 与 handler.rs。WASM 不直接操作页面 2D context。

1. 普通数据

JS object 解成 Rust 结构，再写入 Storage。

文件 解析什么
bridge/opts.rs init 的 width / height / dpr；元素变换、silent、name、draggable、ecData
bridge/shape.rs 各 Shape 的 shape 字段（Rect.r、Sector.r0 等）
bridge/fill_stroke.rs 纯色字符串、线性 / 径向渐变、Pattern 
zr.add(new Rect({
  shape: { x: 8, y: 8, width: 80, height: 40, r: 4 },
  style: { fill: '#5470c6', lineDash: 'dashed' },
}));
// opts.rs + shape.rs + fill_stroke.rs → Path → Storage

2. 函数

on / off / trigger 把 js_sys::Function 存在 registry （实例级在 HANDLER_REGISTRY，图元级在 ELEMENT_REGISTRY）。 命中或 trigger 后 call1，参数是带 zrX / zrY / target 的 packet。 

rect.on('click', (e) => {
  console.log(e.zrX, e.zrY, e.target);
});
zr.handler.dispatch('click', { zrX: 40, zrY: 40 });

有 canvas 时绑定 pointer；mousemove 默认不上屏（避免每帧整幅 RGBA 拷贝）。 拖拽走 element_set_position，非 move 事件才 paint_if_bound。

3. 图像

Pattern / Image 需要已解码的 RGBA。同步路径只认这几种源：

源 要求
Uint8Array 必须带 imageWidth / imageHeight；长度 = 宽 × 高 × 4
HTMLCanvasElement getImageData 抠像素
HTMLImageElement 先画到临时 canvas 再 getImageData；naturalWidth === 0 则失败（未 decode）
URL 字符串 同步路径失败（unsupported pattern image source）。先 new Image() 等 load 
const pat = new Pattern(canvasEl, 'repeat');
rect.setStyle({ fill: pat });

// 无 DOM 时用裸像素：
el.setStyle({
  fill: {
    imageData: rgbaBytes,
    imageWidth: 16,
    imageHeight: 16,
    repeat: 'repeat',
  },
});

回图

zr.refresh() / flush() → Rust Vec<u8> → JS Uint8Array。 绑了 canvas 时，add / attr / 非 mousemove 事件会走 paint_if_bound：同一份 RGBA 做成 ImageData 再 putImageData。 

const rgba = zr.refresh();
ctx.putImageData(
  new ImageData(new Uint8ClampedArray(rgba), zr.width(), zr.height()),
  0,
  0,
);

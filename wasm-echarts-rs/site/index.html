WebAssembly 图表渲染

用 WASM 实现 ECharts 的 canvas 能力，把渲染内核做成可带到其他语言平台的 Rust 库。 宿主只负责把终态图像贴上 canvas，或拿走像素。

起因介绍

官方 ECharts 的 canvas 渲染依赖 JavaScript 与 zrender。本仓库把渲染层迁到 Rust， 经 wasm-bindgen 交给浏览器或其他 WASM 宿主。目标不是再做一个「带 rAF 循环的前端图表库」，而是：

  • 用 WASM 覆盖 ECharts 的 canvas 绘制能力，公开 API 尽量与官方一致
  • 把内核做成纯 Rust 库（rust-zrender），便于 cargo test 像素回归，以及未来到 Wasmer 等非浏览器平台
  • 浏览器只把离屏画好的 RGBA 写回 canvas（或把图像交给外部），WASM 不直接操作 DOM 2D context

因此不做动画中间帧：要的是一帧终态图像，而不是 requestAnimationFrame 循环。 setOption、图元 animate / when().start() 都直接落到最后一组目标属性。

三层定位

三个 crate 职责不重叠。文档站从顶栏进入 wasm-zrender / wasm-echarts。

层 路径 给谁用
rust-zrender crates/rust-zrender 纯 Rust 引擎；无 wasm-bindgen；可 cargo test / 未来 Wasmer
wasm-zrender crates/wasm-zrender 对齐官方 zrender 图元 API；文档站与「直接构图」用户
wasm-echarts crates/wasm-echarts 对齐官方 init / setOption；内部用同一份 ZRenderer，不经第二份 zrender wasm
site → wasm-zrender/js → pkg/ → rust-zrender
site → wasm-echarts/js → pkg/ → rust-zrender

wasm-zrender 与 wasm-echarts 为 sibling，共用同一份 ZRenderer。 echarts 页不得再加载 wasm-zrender/pkg。

从顶栏进入 wasm-zrender 文档 或 wasm-echarts 文档。

已知限制

刻意不做、以及尚未补齐的 canvas 能力（其余按计划对齐，不是永久砍掉）：

  • 仅 canvas：无 SVG painter / hover layer / dirty rect；WASM 出 RGBA，JS 再 putImageData
  • 无动画中间帧 / morph；setOption 与图元动画都是即时终态
  • toolbox DataView 浮层、SaveAsImage DOM 下载条不做；showLoading 不播旋转动画
  • tooltip 以字符串 DOM 为主；图表与组件缺口见 wasm-echarts 文档「未实现」表

总览与何时使用

业务代码走 JS facade（@wasm-echarts）。 pkg/ 是 wasm-bindgen 产出的 handle，给调试或绕过包装。

不要从业务 import '../pkg/wasm_echarts.js'，也不要 new EChartsInstance。echarts 页不要再加载 wasm-zrender/pkg：本模块的 pkg 已经 setNative 进同一套 zrender facade。

何时才碰 pkg

场景 怎么用
文档站 / 业务图表 只 import @wasm-echarts。init 会创建并包装 handle。
Worker chart.worker.js 在 Worker 里 new EChartsInstance。开发者仍写 facade，不必碰 pkg。
调试 / 绕过包装 直接调 native 方法。没有指针绑定、没有 tooltip DOM、没有 useWorker 桥。 
// 推荐（facade）
import initWasm, { init } from '@wasm-echarts';
await initWasm();
const chart = init(canvas);
chart.setOption(option);

// 不要（pkg 构造）
import { EChartsInstance } from '@wasm-echarts';
const handle = new EChartsInstance(480, 360, 1); // 没有 canvas / tooltip

两层对照

JS facade pkg handle
导入 @wasm-echarts → js/ pkg/wasm_echarts.js（内部）
创建 init(canvas, theme?, opts?) new EChartsInstance(width, height, dpr)
setOption 三种官方签名；Worker 返回 Promise set_option(option, opts?)；opts 只有 notMerge / replaceMerge
上屏 / 指针 有 canvas 时自动 blit + 绑事件 没有。需自己 refresh + putImageData
命名空间 graphic / util 等有实现 图元类随 wasm 再导出；工具请走 facade

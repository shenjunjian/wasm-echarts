总览与约定

公开面是 crates/wasm-echarts/js/index.js。 default 是 wasm-bindgen 的 initWasm；命名导出才是 echarts API。

导入

文档站 Vite alias @wasm-echarts 指向 js/。 入口会加载 pkg/wasm_echarts.js，并把同一份模块 setNative 进 wasm-zrender 的 native-core， 因此 echarts 页只持有一份 WASM。 

import initWasm, { init, registerFont } from '@wasm-echarts';

await initWasm();
const chart = init(canvas);
chart.setOption(option);

不要直接 import pkg/wasm_echarts.js，也不要 new EChartsInstance。见 pkg 导出。

default 即 initWasm 补充

与 wasm-bindgen --target web 一致：默认导出是异步加载 .wasm 的函数。官方 echarts 没有这一步；这是 WASM 宿主必需。

参数 类型 说明
module_or_path? string | URL | Request | Response | BufferSource 可选。不传则按打包路径加载 wasm_echarts_bg.wasm 
import initWasm from '@wasm-echarts';
await initWasm();

构造约定

facade 的实例类是 ECharts（js/instance.js），包装 native EChartsInstance 或 Worker 桥 ChartWorkerBridge。 业务只通过 init() 拿到实例，不要自己 new。

  • useWorker 只出现在 init 的第三参数 opts，不是 option 字段，也不是实例方法。
  • 同一 canvas 上已有未 dispose 的实例时，init 会 warn 并返回已有实例。
  • 绑了 canvas 时，把 canvas.width / canvas.height 设成与 opts 一致；上屏不改位图尺寸。
const chart = init(canvas);
const workerChart = init(canvas, null, { useWorker: true });
